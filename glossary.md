# Glossary — Architectural Guardrail

- **Adapter layer** — app-owned middle layer that holds features a third-party provider can't (e.g. roles beyond a provider's cap) so provider swaps are localized changes (Ch 8)
- **Architectural guardrail** — the full layered system (mindset, patterns, types, block, DB isolation, CLAUDE.md, script) that keeps AI writing good code as an app grows; a.k.a. guardrail coding (Ch 1, Ch 3)
- **Audit log block** — tracing built once into the protected procedure; automatically knows resource, customer, and member for every action (Ch 13)
- **Base procedure** — middleware-owned procedure that public and protected procedures chain onto, so app-wide concerns like rate limiting live in one place (Ch 13)
- **Block / block layer** — the single gate all traffic passes through before hitting the server; bundles session, plan check, resources, audit, permissions, rate limiting (Ch 10)
- **Client mirror** — the client side mirroring the same globalized patterns so AI sees one shape everywhere (Ch 13)
- **Code drift** — AI inventing its own pattern when it sees inconsistent code; creativity is drift (Ch 4)
- **ctx object** — per-endpoint server object carrying the logged-in user's session; org ID is injected server-side from it, never trusted from the prompt (Ch 12)
- **Database isolation** — separation of business logic from database logic behind a service layer + Prisma, so DB providers swap at ~zero cost (Ch 11)
- **Echo signal** — a structured lint/type/build error fed back to AI mid-build that carries the pattern; AI fixes errors but ignores docs (Ch 3, Ch 4, Ch 7)
- **Gap Method** — deliberately stubbing the second task ("log to console for now") so a loudly-marked gap is filled later instead of being forgotten (Ch 18)
- **Globalization** — extracting logic repeated across layers into one shared helper that runs identically on server and client (Ch 5)
- **GrabScript** — the guardrail script (transcript also renders "GRP script"/"Grabcript"): given a path, lists candidate files, filters by SOT keywords, and only then opens survivors (Ch 16)
- **Guardrail coding** — building apps only with AI, protected by the architectural guardrail system (Ch 1)
- **Inline injection** — comments placed at the top of code blocks answering What/Why/How/Where, delivering tiny context at the moment AI reads that code (Ch 15)
- **Linear flow / linear path** — the mappable sequence AI walks by imitating existing code; if you can't map it, no pattern exists yet (Ch 3, Ch 4)
- **Microcontext injection** — delivering tiny pieces of context to AI at the time it needs them instead of dumping documentation (Ch 15)
- **Normalizing identity** — extracting the common things from a provider into an app-owned shape; every connection layer mirrors into one shared adapter (Ch 8)
- **Orchestrator file** — CLAUDE.md as the single file connecting every guardrail concept; pattern-recognition rules first, kept short (Ch 17)
- **Pattern recognition** — teaching AI to recognize and reuse existing patterns; "never invent your own architecture, verify a pattern exists" (Ch 4, Ch 17)
- **Protected procedure / protectedRoute** — the canonical guarded endpoint wrapper AI copies by name; chains org scoping, permissions, plan gates, rate limits, pagination, usage counter, audit (Ch 10, Ch 11)
- **Registry layer** — the module whose resource definitions AI finds via search and copies verbatim; the source of truth AI should copy instead of reason about (Ch 6)
- **Resource** — named capability with name, description, upgrade message, limit, and permissions; the source-of-truth object gates, nav, and upgrade prompts derive from (Ch 5, Ch 6)
- **Router layer** — business-level logic controlling what a user can do; consumes services, never the DB directly (Ch 11)
- **Server-only** — `import "server-only"` at the top of a service file so the code is excluded from the client bundle and cannot be called client-side (Ch 9)
- **Service layer** — the only files that touch the database; server-only, accessed through the router (Ch 11)
- **SOT keyword** — searchable term in inline docs naming/locating the source of truth, used by GrabScript to filter files (Ch 16)
- **TypeScript lockin** — all types dynamically derived from one source (e.g. `keyof typeof`), never hardcoded, so wrong usage errors everywhere (Ch 7)
- **Vibe coding** — prompting an app into existence with no structural system; the worst way to build (Ch 1)
- **White Line Method** — making a false claim that forces AI to search for something that supposedly exists, steering it to existing code instead of duplication (Ch 18)
